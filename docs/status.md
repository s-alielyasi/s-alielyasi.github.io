# وضعیت پروژه و کارهای باقی‌مانده

تاریخ بازبینی: **۲۰۲۶-۱۰-۱۵**. این گزارش سورس محلی، تست‌های اجراشده و بررسی عمومی دامنه/گیت‌هاب را از عملیات نیازمند احراز هویت جدا می‌کند. شاخهٔ آمادهٔ PR: `feat/pages-ci-and-project-completion`؛ شاخهٔ مقصد: `master`.

## نتیجهٔ بررسی‌های انجام‌شده

- **۴۸ تست مرورگر، بدون شکست و بدون retry** در محیط Ubuntu 24.04 اجرا شدند: Chrome 155، Firefox 157 و WebKit 27.2 در پروژه‌های دسکتاپ، موبایل Chromium، iPhone/WebKit و iPad/WebKit. به دلیل محدودیت جغرافیایی دریافت Chrome for Testing، پروژه‌های Chromium از Google Chrome نصب‌شده استفاده کردند. کانتینر تست دسترسی شبکهٔ بیرونی نداشت.
- هر چهار بخش، کلیک/لمس ناوبری، حالت افقی، نبود overflow افقی و clipping، چرخهٔ کامل Tab، Enter، لینک پرش، وضوح فوکوس، ناوبری بدون JavaScript، متن ۲۰۰٪ در عرض ۳۲۰px، metadata و فایل‌های artifact بررسی شدند. axe در قواعد انتخاب‌شدهٔ WCAG 2 A/AA، 2.1 و 2.2 AA نقضی گزارش نکرد؛ این نتیجه گواهی انطباق کامل نیست.
- **بزرگ‌نمایی واقعی ۲۰۰٪ مرورگر Firefox 136** جداگانه بررسی شد: با ثابت ماندن فونت روت، DPR از ۱ به ۲ و viewport محتوایی از ۱۲۸۰ به ۶۴۰ تغییر کرد؛ چهار بخش، نبود overflow و دسترسی به آخرین دکمه تأیید شدند. این آزمایش با تغییر اندازهٔ متن روت تفاوت دارد.
- **۵ تست HTTPS محلی** با `npm run test:release` گذشتند: پذیرش خروجی یکسان، رد عنوان قدیمی حتی با Open Graph صحیح، رد HTML قدیمی، رد CSS قدیمی و رد HTTP ساده. اعتبارسنجی TLS غیرفعال نشد؛ فقط گواهی موقت fixture به فرایند همان تست معرفی شد.
- `npm run check`، ساخت `dist/`، هماهنگی manifest/lockfile، ساختار YAML، شرط‌های انتشار، قفل SHA اکشن‌ها و `git diff --check` بررسی شدند. وابستگی‌ها فقط توسعه‌ای‌اند؛ نصب اولیهٔ npm پنج پکیج و صفر آسیب‌پذیری گزارش کرد.
- GET عمومی `https://ali-elyasi.ir/` پاسخ ۲۰۰ با TLS معتبر داشت؛ DNS سیستم به `185.199.108.153` رسید. **نسخهٔ زنده هنوز عنوان قدیمی «وب‌سایت شخصی علی الیاسی» را دارد** و انتشار این تغییرات تأیید نشده است.
- API عمومی مخزن، شاخهٔ پیش‌فرض `master` و `has_pages: true` را نشان داد. فهرست عمومی Actions در زمان بررسی اجرای ثبت‌شده نداشت. درخواست بدون احراز هویت به API تنظیمات Pages پاسخ ۴۰۴ داد؛ از این پاسخ نمی‌توان Source یا وضعیت HTTPS پنل را نتیجه گرفت.
- نتیجهٔ تاریخ‌دار GET لینک‌ها در [link-checks.json](link-checks.json) است: دامنه، ویرگول، GitHub و زرین‌پال پاسخ ۲۰۰؛ LinkedIn پاسخ ۹۹۹، Goodreads پاسخ ۴۰۳، Google Forms پاسخ ۴۰۱ و Telegram خطای شبکه داشتند. مقصدی با ۴۰۴/۴۱۰ تأیید نشد؛ پاسخ محدودیت دسترسی به معنی حذف مقصد نیست.

گزارش مرورگر و تصاویر، خروجی محلی `playwright-report/` هستند و در گیت ثبت نمی‌شوند؛ workflow نیز گزارش هر اجرای آینده را به‌صورت artifact نگه می‌دارد. نتایج فوق اجرای محلی‌اند و به معنی موفقیت CI گیت‌هاب نیستند.

## کارهای باقی‌مانده و وابستگی آن‌ها

| موضوع | وضعیت واقعی | اقدام لازم |
| --- | --- | --- |
| push و ساخت PR | انجام نشده؛ ابزار GitHub اکنون فعال و حساب احراز هویت شده است، اما انتقال اولین blob با 403 رد شد؛ فهرست installationها و حساب‌های نصب‌شده خالی است | نصب/اعطای دسترسی GitHub App به همین مخزن یا احراز هویت Git محلی، سپس push شاخه و ساخت PR به `master` با متن آماده |
| تنظیم و انتشار Pages | workflow محلی آماده است؛ Actions در بازبینی فعلی صفر اجرا دارد؛ ابزار اتصال مسیر API تنظیمات Pages را پشتیبانی نمی‌کند؛ سایت زنده هنوز قدیمی است | پس از رفع دسترسی، خواندن تنظیم موجود، انتخاب GitHub Actions با حفظ دامنه، اجرای checks و ادغام PR برای deploy؛ سپس تأیید HTTPS و نسخهٔ زنده |
| موبایل/تبلت واقعی و صفحه‌خوان | شبیه‌سازی و تست خودکار انجام شدند؛ تست انسانی روی سخت‌افزار انجام نشده | بررسی روی دستگاه واقعی، Safari دستگاه Apple و صفحه‌خوان با ابزار مناسب |
| لینک‌های دارای محدودیت | مالکیت/محتوا پشت پاسخ محدود یا شبکه تأیید نشده | باز کردن مقصدها در محیط قابل دسترس؛ به‌ویژه بررسی دسترسی عمومی فرم در حساب مالک، بدون ارسال فرم یا پرداخت آزمایشی |
| SEO پس از انتشار | metadata محلی تأیید شده؛ ایندکس، canonical انتخابی موتور جست‌وجو و پیش‌نمایش زنده تأیید نشده‌اند | بررسی پس از deploy و در صورت نیاز با Search Console مالک |

اجازهٔ مالک برای اتصال و ساخت PR دریافت شده است. در ادامهٔ کار در **۲۰۲۶-۱۰-۱۵**، ابزارهای GitHub در دسترس بودند و پروفایل مالک و مخزن خوانده شدند. metadata مخزن برای حساب مالک `admin/push: true` نشان داد، اما این مقدار مجوز خود اتصال را اثبات نمی‌کند. انتقال اولین blob از طریق اتصال با پاسخ زیر رد شد؛ هیچ blob، tree، commit یا شاخه‌ای روی GitHub ایجاد نشد و تاریخچهٔ موجود محلی بازنویسی نشد:

```text
403: Resource not accessible by integration
```

فهرست installationها و حساب‌های نصب‌شدهٔ قابل مشاهدهٔ اتصال هر دو خالی بودند. جست‌وجوی شاخهٔ `feat/pages-ci-and-project-completion` و PR متناظر نتیجه‌ای نداشت؛ HEAD شاخهٔ remote `master` همچنان `6c7589f258ae9bf305fcaed437a0fa51b149caeb` بود. ارسال مستقیم با شبکهٔ مجاز نیز به دلیل نبود اعتبارنامه شکست خورد:

```text
fatal: could not read Username for 'https://github.com': terminal prompts disabled
```

API فهرست Actions و workflowها هر دو مقدار `total_count: 0` برگرداندند. آخرین deployment قابل مشاهدهٔ محیط `github-pages` با شناسهٔ `600856728` روی کامیت `6c7589f` بود؛ وضعیت آن در `2022-07-10T15:01:54Z` برابر `success` ثبت شده است. این deployment قدیمی به شاخهٔ فعلی مربوط نیست. ابزار اتصال درخواست `/pages` را به دلیل خارج بودن از مسیرهای پشتیبانی‌شده رد کرد؛ این خطا پاسخی از تنظیمات واقعی Pages نیست. API عمومی بدون احراز هویت برای `/pages` و `/pages/builds/latest` پاسخ ۴۰۴ داد؛ این پاسخ نیز Source یا تنظیم HTTPS پنل را مشخص نمی‌کند. GET مستقل دامنه با اعتبارسنجی عادی TLS پاسخ ۲۰۰ داد؛ عنوان همچنان «وب‌سایت شخصی علی الیاسی» بود و hash HTML با سورس شاخه تفاوت داشت. بنابراین PR، اجرای CI و انتشار نسخهٔ جدید تأیید نشده‌اند. تست‌های محلی قبلی در این ادامه دوباره اجرا نشدند؛ `npm` در محیط فعلی موجود نیست.

کامیت‌های این مرحله شامل `09bc1fb` برای مجوز، `3e62322` برای محتوا/دسترس‌پذیری و `08bcda7` برای تست و انتشار هستند؛ گزارش نهایی و متن PR در کامیت مستندات بعدی نگه‌داری می‌شوند.

## ادامه پس از رفع دسترسی GitHub

اتصال احراز هویت شده و ابزارهای آن بارگذاری شده‌اند؛ مانع فعلی، مجوز انتقال محتواست. نصب/دسترسی GitHub App برای `s-alielyasi/s-alielyasi.github.io` باید در [تنظیمات installationهای GitHub](https://github.com/settings/installations) بررسی و تکمیل شود. مسیر جایگزین، احراز هویت Git محلی در محیط کاربر است؛ اعتبارنامه نباید در چت یا مخزن ثبت شود.

پس از رفع دسترسی، شاخهٔ `feat/pages-ci-and-project-completion` با تاریخچهٔ موجود push و PR به `master` با عنوان و متن `docs/pull-request.md` ساخته شود. وضعیت واقعی checks، تنظیمات Pages با حفظ دامنه و نسخهٔ HTTPS خوانده و گزارش شوند. صرف ساخت PR باعث انتشار نمی‌شود؛ انتشار workflow پس از ادغام در `master` است. در این ادامه هیچ ادغام یا تغییر تنظیمات Pages انجام نشده است.

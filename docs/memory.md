# حافظهٔ پروژه

تاریخ اسکن اولیه و آخرین به‌روزرسانی ساختار/محتوا: **۲۰۲۶-۱۰-۱۵**. این سند وضعیت فایل‌های checkout محلی را ثبت می‌کند؛ تأیید زندهٔ دامنه، لینک‌های بیرونی یا تنظیمات حساب GitHub نیست.

## هدف و معماری

سایت شخصی علی الیاسی برای معرفی، دریافت رزومه، ارتباط و ثبت سفارش خدمات طراحی سایت و تست/تضمین کیفیت نرم‌افزار است. رابط فارسی است و `lang="fa"` دارد.

پیاده‌سازی کاملاً استاتیک و بدون فریم‌ورک، backend، پایگاه داده یا وابستگی پکیجی است. در زمان اسکن `package.json`، lockfile، ابزار build، تست خودکار، CI، `.github/workflows`، `.nojekyll` یا فایل `LICENSE` وجود نداشت. این موارد بیان وضعیت فعلی‌اند و الزام به اضافه کردن همهٔ آن‌ها نیستند.

## نقشهٔ فایل‌ها

دایرکتوری‌های محیطی `.agents`، `.codex` و `.aws` در checkout دیده شدند اما در زمان اسکن فایل قابل مشاهده و trackشده‌ای در آن‌ها نبود. محتویات داخلی `.git` جزو سورس سایت نیست؛ وضعیت گیت، فهرست فایل‌های trackشده و پنج پیام commit اخیر بررسی شد. تاریخچهٔ کامل و تنظیمات خصوصی گیت اسکن نشدند.

## رفتار فعلی

- پنل‌های `st-panel-1` تا `st-panel-4` به‌ترتیب خانه، رزومه، تماس با من و ثبت سفارش هستند. بخش خانه عنوان `h1` دارد و بخش‌های بعدی `h2` دارند. صفحه `lang="fa"` و `dir="rtl"` دارد.
- چهار لینک `.st-push` در نوار ثابت پایین صفحه با حداقل ارتفاع `3.5rem` به‌علاوهٔ safe area قرار دارند. هر لینک به شناسهٔ پنل مربوط می‌رود؛ لینک‌ها بدون JavaScript و با کیبورد هم کار می‌کنند.
- JavaScript وضعیت `aria-current="location"` را بر اساس پنلی که از خط ۴۰٪ ارتفاع viewport گذشته به‌روز می‌کند. رویدادهای scroll با `requestAnimationFrame` تجمیع می‌شوند و resize، hashchange، pageshow و آماده شدن فونت نیز وضعیت را به‌روز می‌کنند.
- رنگ اصلی `#0d9b9b`، رنگ فعال `#086f6f` و پس‌زمینهٔ پنل‌ها متناوب سفید و فیروزه‌ای است. اسکرول نرم بومی است و با `prefers-reduced-motion` غیرفعال می‌شود.
- صفحه اسکرول طبیعی دارد. پنل‌ها حداقل `100svh` ارتفاع دارند (با fallback به `100vh`) و با محتوای بلند رشد می‌کنند؛ `overflow: hidden` پنل فقط تزئین بالای آن را محدود می‌کند و ارتفاع ثابتی وجود ندارد. فاصلهٔ پایین پنل‌ها برای نوار ناوبری و safe area رزرو شده است.
- فونت اصلی Vazir نسخهٔ 30.1.0 با `font-display: swap` از `assets/fonts/vazir/font-face.css` بارگیری می‌شود. وزن‌های ۱۰۰، ۳۰۰، ۴۰۰، ۵۰۰، ۷۰۰ و ۹۰۰ فایل واقعی دارند؛ وابستگی اجرایی به CDN یا اسکریپت بیرونی وجود ندارد. منبع، integrity و مجوز در README پوشهٔ فونت ثبت شده‌اند.
- اندازهٔ عنوان‌ها، فاصله‌ها و تزئین با `clamp` تنظیم می‌شود. در عرض حداکثر `36rem` لینک‌های دکمه‌ای تمام‌عرض می‌شوند؛ در حالت افقی با ارتفاع حداکثر `38rem` تزئین و فاصله‌ها کوچک‌تر و لینک‌های تماس دو ستونه می‌شوند. لینک‌های تماس حداقل هدف لمسی ۴۴px دارند. متن قابل انتخاب است و لینک‌ها فوکوس قابل مشاهده دارند.
- تنها لینک رزومه به PDF انگلیسی داخل مخزن می‌رود. رزومهٔ فارسی و فایل آن حذف شده‌اند. بخش تماس به Telegram، LinkedIn، GitHub، Virgool و Goodreads لینک دارد؛ Zeeg، Stackshare، Spotify و Clubhouse بنا به درخواست مالک حذف شده‌اند.
- ثبت سفارش به Google Forms و پرداخت به Zarinpal هدایت می‌شود؛ پردازش فرم یا پرداخت در این مخزن پیاده‌سازی نشده است.

## اجرای محلی

از روت پروژه:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

صفحه در `http://127.0.0.1:8000` در دسترس است. فایل‌های روت مستقیماً سرو می‌شوند؛ دستور build یا نصب وجود ندارد. نام مخزن و `CNAME` با میزبانی GitHub Pages سازگارند، ولی branch انتشار، تنظیمات Pages، DNS و HTTPS از فایل‌های محلی مشخص نمی‌شوند.

## یافته‌های باز برای تسک‌های بعدی

موارد زیر پس از به‌روزرسانی ساختار و محتوا همچنان باز هستند. اولویت دقیق آن‌ها به درخواست بعدی بستگی دارد.

| حوزه | یافته | اثر یا بررسی پیشنهادی |
| --- | --- | --- |
| معرفی و SEO | عنوان، `h1` و favicon موجود است؛ توضیح meta، canonical و Open Graph وجود ندارد | در تسک معرفی یا SEO بررسی شود |
| مجوز | مجوز OFL 1.1 و attribution فونت موجود است؛ فایل مستقل مجوز کد پروژه وجود ندارد | تعیین مجوز کد پروژه بر عهدهٔ مالک است |

## سیاست فایل‌های عمومی و ignore

فایل‌های HTML/CSS/JS، فونت، تصویر، PDFهای لینک‌شده، `CNAME` و مستندات بخشی از محتوای عمومی پروژه هستند و نباید با الگوهای کلی مثل `*.pdf` یا `docs/` پنهان شوند.

`.gitignore` اکنون فایل‌های محیط واقعی، کلیدهای خصوصی رایج، پوشهٔ محلی AWS، خروجی و cache ابزارهای محلی، log، فایل‌های موقت و تنظیمات شخصی ویرایشگر را پوشش می‌دهد. فایل‌های نمونهٔ `.env.example` و `.env.*.example` قابل track هستند و باید فقط مقدار نمونه داشته باشند. وجود الگو برای خروجی یک ابزار به معنی نصب یا استفادهٔ فعلی آن ابزار نیست.

در اسکن الگویی فایل‌های متنی trackشده، نشانه‌ای از هدر کلید خصوصی، قالب رایج token گیت‌هاب، شناسهٔ access key آمازون یا انتساب آشکار secret پیدا نشد. این بررسی محدود، جایگزین ممیزی امنیتی یا اسکن تاریخچه نیست. PDF انگلیسی فعلی متن قابل استخراج دارد، رمزگذاری نشده است و `pdfinfo` برای آن JavaScript گزارش نکرد. اطلاعات عمومی آن عمداً از طریق سایت در دسترس است؛ `.gitignore` اثری بر آن یا داده‌های موجود در تاریخچه ندارد. حذف رزومهٔ فارسی فقط روی نسخهٔ فعلی اعمال شده و تاریخچهٔ گیت بازنویسی نشده است.

## دامنه و نتیجهٔ بررسی اولیه

- تمام ۱۰ فایل اصلی trackشده بررسی شدند: فایل‌های متنی کامل خوانده شدند، favicon دیده شد، metadata فونت و metadata و متن هر دو PDF بررسی شد.
- هر شش ارجاع محلی HTML و CSS به فایل موجود می‌رسید: CSS، JavaScript، favicon، فونت و دو رزومه.
- ارجاع‌های خارجی شناسایی شدند؛ اعتبار مقصد آن‌ها و دامنهٔ زنده بررسی نشده است.
- پیش از مستندسازی اولیه، worktree تغییر ثبت‌نشده نداشت. آن تسک فقط راهنما، حافظهٔ پروژه و `.gitignore` را تغییر داد.
- مرورگر، ارزیابی بصری صفحات و اجرای JavaScript در این اسکن انجام نشده‌اند. نبود ابزار تست در پروژه به معنی تأیید رفتار در همهٔ مرورگرها نیست.
- قواعد ignore با ۱۵ مسیر عمومی/نمونه و ۲۱ مسیر محلی/حساس بررسی شدند؛ فایل‌های عمومی قابل track و مسیرهای محلی مورد انتظار نادیده گرفته شدند. لینک نسبی راهنما، UTF-8 و فاصله‌های انتهای خط مستندات و `git diff --check` نیز بررسی شدند.
- تلاش برای بررسی دریافت فایل‌ها روی HTTP محلی به دلیل ممنوع بودن ایجاد socket در sandbox اجرا نشد؛ وجود هر شش فایل ارجاع‌شده به‌صورت مستقیم بررسی شد.


## به‌روزرسانی قبلی ساختار و محتوا

- CSS، JavaScript، فونت و favicon از روت و پوشه‌های قدیمی به زیرپوشه‌های مشخص در `assets/` منتقل شدند. مسیر فونت در آن مرحله `../fonts/Vazir-Regular.ttf` بود و در تسک بعدی با پکیج اصلی وب‌فونت جایگزین شد؛ فایل عمومی رزومه همچنان در `resumes/` است.
- مسیر عمومی `resumes/AliElyasi_Resume_English.pdf` حفظ و محتوای آن بدون تغییر با فایل `Ali-Elyasi-Resume-B2C.pdf` ارائه‌شده توسط مالک جایگزین شد. متن سند فقط به‌عنوان محتوای رزومه بررسی شد.
- فایل و لینک رزومهٔ فارسی و چهار لینک تماس درخواستی حذف شدند؛ پنج لینک تماس باقی مانده‌اند.
- شناسه‌های تکراری و شناسه‌های بدون استفادهٔ بخش سفارش حذف شدند. لینک‌های رزومه، پرداخت و فرم اکنون مستقیماً با کلاس `action-link` نمایش داده می‌شوند و `button` تو‌در‌تو ندارند. ظرف مشترک آن‌ها کلاس `actions` دارد.
- استایل لینک‌های دکمه‌ای با چیدمان قبلی هماهنگ و فوکوس آن‌ها قابل مشاهده شد. انتخابگرهای بی‌اثر `.st-container > a` حذف شدند. هر شش لینک بازشونده در تب جدید `rel="noopener noreferrer"` دارند.
- README و راهنمای عامل‌ها با ساختار جدید هماهنگ شدند. معماری استاتیک، چهار پنل، ترتیب ناوبری و منطق JavaScript تغییری نکردند.
- بررسی نهایی: تطابق بایتی PDF جدید با فایل ارائه‌شده، سالم بودن پنج ارجاع محلی، حذف مقصدهای درخواستی، یکتایی شناسه‌های HTML، نبود عناصر تعاملی تو‌در‌تو و تطابق بایتی JavaScript/فونت/favicon با نسخهٔ قبل بررسی شدند. تست مرورگری انجام نشد.


## فونت اصلی و چیدمان موبایل/تبلت

- شش وزن استاندارد وب از پکیج اصلی `vazir-font@30.1.0` پس از تطبیق SHA-512 آرشیو با metadata رسمی npm کپی شدند. فایل‌های فونت، `OFL.txt` و `AUTHORS.txt` بدون تغییر نگه‌داری می‌شوند. TTF قدیمی نسخهٔ 27.2.1 حذف شده است.
- CSS فونت مستقل و محلی است. فرمت‌های قدیمی و variantهای استفاده‌نشده برای سبک ماندن سایت اضافه نشده‌اند؛ نصب npm یا build لازم نیست.
- لینک توییتر از README حذف شد.
- جابه‌جایی پیکسلی پنل‌ها با جریان طبیعی صفحه، لینک‌های hash و حداقل ارتفاع قابل رشد جایگزین شد. `nav`، `main`، عنوان اصلی، جهت RTL و لینک پرش به محتوا اضافه شدند. تماس‌ها فهرست معنایی دارند و جهت متن ترکیبی هر لینک خودکار است.
- تغییرات برای موبایل و تبلت، حالت افقی، بزرگ‌نمایی متن، لمس، استفاده با کیبورد و ترجیح کاهش حرکت طراحی شده‌اند؛ نوار پایین و نواحی ایمن صفحه در فاصله‌گذاری لحاظ می‌شوند.
- بررسی مرورگری با Firefox 136 روی HTTP محلی در ۱۱ viewport انجام شد: `320×640`، `360×640`، `390×844`، `430×932`، `576×800`، `768×1024`، `820×1180`، `1024×768`، `1440×900`، `640×360` و `844×390`. هر چهار پنل، وضعیت فعال ناوبری، بارگیری فونت، نبود overflow افقی، نداشتن محتوای بریده‌شده و ارتفاع هدف‌های لمسی بررسی شدند. تصاویر نمایندهٔ موبایل، تبلت و حالت افقی هم دیده شدند.
- متن ۲۰۰٪ در عرض ۳۲۰px، دسترسی به آخرین دکمهٔ سفارش بالای نوار پایین، فعال‌سازی لینک ناوبری با Enter و کارکرد لینک‌ها با JavaScript غیرفعال تأیید شدند. پس از تنظیم حالت افقی، هر دو viewport افقی دوباره بررسی و دیده شدن همهٔ لینک‌های تماس بالای نوار تأیید شد.
- PDF، WOFF2 و مجوز با پاسخ HTTP موفق و محتوای بایتی صحیح دریافت شدند. ارجاع‌های HTML/CSS، هدف‌های hash، یکتایی شناسه‌ها و تطابق فایل‌های فونت/مجوز با پکیج اصلی بررسی شدند. این ارزیابی شبیه‌سازی اندازه‌ها در Firefox دسکتاپ است؛ تست روی دستگاه واقعی یا Safari انجام نشده است.
